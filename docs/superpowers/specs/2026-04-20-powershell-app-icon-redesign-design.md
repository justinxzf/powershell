# PowerShell 应用图标重设计

## Context

当前应用使用 `Sources/PowerShell/Resources/AppIcon.png` 在运行时通过 `Sources/PowerShell/App/PowerShellApp.swift:250` 设置应用图标。现有图标虽然已经替换成功，但在 Dock 中与其他 macOS / 开发者工具类应用并排时显得不够精致，主要问题是主体造型偏土、发光过强、图标语言更像一张临时素材图，而不是成熟应用图标。

用户已经明确希望把图标优化到“和其他应用一样美观”的水平，并确认了以下审美方向：

- 图标方向：终端窗口
- 气质：极简高级
- 主色：黑灰底 + 青蓝微光
- 语义保留：只保留终端类符号语义（如 `>_` / 光标），不沿用旧 logo 主体造型

本次设计不仅要更新视觉稿，还要把当前“运行时加载单张 PNG”的方案升级为标准 macOS AppIcon 资源方案，以提高 Dock、Finder、应用包显示的一致性。

## 目标

- 设计一套更接近成熟 macOS 工具类应用的 PowerShell 图标
- 保留“终端应用”的一眼可识别语义
- 在 Dock 中与系统应用和开发者工具图标并排时不突兀
- 控制整体气质为克制、专业、精致，而不是炫技或廉价霓虹
- 升级为标准 macOS 图标资源交付方式，避免仅替换单张 PNG 带来的显示不一致问题

## 推荐方案

采用“极简终端窗口”方案：

1. 使用 macOS 风格圆角方形底座作为图标外轮廓
2. 底座采用深黑灰渐变，提供轻微玻璃/金属质感
3. 中心放置简化后的终端窗口轮廓，不做真实截图式细节
4. 仅保留 `>_` / 光标作为终端识别符号，并进行几何化、精致化处理
5. 青蓝色仅作为微光强调色，用于符号和局部边缘高光
6. 产出 1024x1024 基础图，并生成标准 macOS AppIcon 资源尺寸
7. 用 `AppIcon.appiconset` / `.icns` 路径替代当前运行时单图设置方式

## 视觉设计说明

### 1. 造型结构

图标主体为标准圆角方形底座，轮廓应接近 macOS Big Sur 之后常见应用图标语言。中心元素不是完整 UI 截图，而是“终端窗口”的抽象表达：

- 有窗口感，但没有复杂工具栏、菜单或大量内部细节
- 使用一层极轻的窗口轮廓或顶边结构暗示“terminal window”
- 避免做成带红黄绿三按钮的强拟物窗口截图，减少廉价感

### 2. 识别元素

保留终端语义，但不保留旧 logo 形状：

- `>_` 是唯一核心识别元素
- `>` 与 `_` 使用更规整的等宽字符几何比例
- 符号位置在视觉中心略偏上，保证缩小后仍可读
- 不加入额外图案、文字、品牌首字母或复杂装饰

### 3. 配色与光效

整体基调为深黑灰 + 青蓝微光：

- 背景：黑灰渐变，避免纯黑死板
- 轮廓：用低对比高光表现材质，不做高饱和边框
- 符号：青蓝色，但亮度控制在“高级工具感”，而非强霓虹
- 光效：只保留一层弱发光和局部环境光，避免多层发光、炫光、粒子感

### 4. 材质与细节

材质目标不是“赛博朋克”，而是“安静、精致、专业”：

- 底座拥有轻微玻璃/金属质感，但不夸张反射
- 终端窗口边界线条为低对比细线，避免真实界面截图感
- 阴影要稳重，强调体积，不强调戏剧化漂浮
- 整体看起来应该更接近专业 macOS 工具图标，而不是 AI 生成海报缩略图

## 实现方案

### 1. 资源交付

从交付方式上切换为标准 macOS 图标资源：

- 新增标准 `AppIcon.appiconset`
- 以 1024x1024 主稿为源，导出 macOS 所需尺寸
- 若当前 SPM 应用结构对原生 AppIcon 支持有限，则补充 `.icns` 资源并在应用打包链路中接入
- 当前 `Sources/PowerShell/Resources/AppIcon.png` 仅作为过渡方案，不应继续作为最终图标接入路径

### 2. 代码改动范围

预计主要影响：

- `Package.swift`：资源声明可能调整
- `Sources/PowerShell/App/PowerShellApp.swift`：移除或收敛运行时 `NSApp.applicationIconImage` 设置逻辑
- 图标资源目录：新增标准图标资源集或 `.icns` 文件

### 3. 保持不变的内容

本次不改动：

- 终端功能、会话管理、LLM 逻辑
- 设置页、标题栏、通知逻辑
- 用户可见文案

## 备选方案与取舍

### 方案 A（推荐）：极简终端窗口

优点：

- 终端语义清晰
- 与 macOS 工具类应用的审美最接近
- 既有识别度，又不过于花哨

缺点：

- 需要严控细节，否则容易变成“普通深色窗口图标”

### 方案 B：悬浮玻璃终端

优点：

- 更现代，材质感更强
- 视觉上更精致

缺点：

- 容易过度设计
- 在 Dock 中可能比目标更抢眼

### 方案 C：单符号终端徽章

优点：

- 缩小后识别度非常强
- 实现更稳定

缺点：

- “终端窗口”方向不够明显
- 与用户已确认的方案不一致

## 验证标准

### 视觉验收

成功标准：

1. 图标在 Dock 中不显土、不显廉价
2. 缩小后能一眼看出是终端类应用
3. 与周围系统或开发者工具图标并排时不突兀
4. 整体气质是克制、专业、精致，而不是高饱和炫技

### 技术验收

1. 图标资源通过标准 macOS 方案接入
2. 应用启动后 Dock 图标正确显示
3. Finder / 应用包图标与 Dock 呈现保持一致或尽量一致
4. `swift build` 通过
5. 如环境允许，运行 `swift run PowerShell` 进行人工确认

## 非目标

以下内容不在本次范围内：

- 设计新的品牌字体或字标
- 调整应用名称
- 重做窗口内 UI 主题
- 增加动态图标或状态图标
- 扩展为 iOS / iPadOS 多平台图标体系
