# 通知栏视觉与堆叠优化设计

## Context

当前 debug 模式下的通知由 `Sources/PowerShell/Services/NotificationManager.swift` 内嵌的 `FloatingNotificationBanner` 负责展示，使用单个 `NSPanel` 在右上角滑入。现状有两个明显问题：

1. 视觉层次较弱，卡片信息堆在一起，关闭按钮、标题和正文缺少清晰分层。
2. 多条通知共享同一个右上角目标位置，连续出现时会直接重叠，影响可读性和操作。

本次目标是在不改变通知来源和点击跳转能力的前提下，重做 debug 模式下的浮动通知体验，使其更美观、更紧凑，并且能稳定处理多条通知同时存在的场景。

## 目标

- 将当前浮动通知重做为更紧凑的信息卡片风格
- 保持深色体系，但增强层次、间距、圆角和关闭按钮的视觉质量
- 多条通知采用右上角纵向堆叠展示，不再重叠
- 同时最多展示 3 条通知，超过部分折叠为 `+N` 聚合提示
- 通知默认常驻，直到用户点击卡片或手动关闭
- 点击通知仍跳转到对应 session
- 不改变 App Bundle 模式下的原生系统通知行为

## 推荐方案

采用“紧凑卡片 + 纵向堆叠 + 超出折叠”的方案：

1. 将现有单体 `FloatingNotificationBanner` 拆成通知数据模型、通知栈管理器、单卡片面板三部分
2. 所有 debug 通知先进入栈管理器，再由栈管理器统一决定展示顺序、位置和聚合状态
3. 每张卡片采用紧凑信息卡片样式，限制正文长度，减少对终端区域的遮挡
4. 右上角最多显示 3 张可见卡片，超过的通知不继续下压布局，而是收敛到最底部的 `+N` 聚合卡片中
5. 通知不自动消失，仅在点击卡片进入会话或点击关闭按钮时移除

该方案兼顾了视觉优化、可读性和交互稳定性，且与当前浮动通知的使用习惯最接近，落地风险最低。

## 备选方案与取舍

### 方案 A（推荐）：紧凑卡片 + 纵向堆叠 + 超出折叠

优点：

- 最符合“短而利落、避免遮挡终端”的目标
- 多条通知结构稳定，补位逻辑明确
- 容易延续现有右上角浮层心智模型
- 后续可平滑扩展排序、分组等能力

缺点：

- 需要引入通知栈管理逻辑，而不是继续使用单个面板

### 方案 B：主卡片 + 次级缩略堆叠

优点：

- 视觉表现更强，层叠感更明显

缺点：

- 次级卡片信息承载不稳定
- 点击、关闭、补位规则更复杂
- 对当前场景来说设计感收益高于实际可用性收益

### 方案 C：抽屉式通知中心

优点：

- 几乎不遮挡终端

缺点：

- 需要额外一步展开操作
- 不适合即时提醒
- 已偏离当前“浮动通知”产品形态

## 组件设计

### 1. NotificationManager

保留 `send(title:body:sessionId:)` 作为统一入口，但在 fallback 路径中不再直接创建单个面板，而是改为将通知投递给通知栈。

App Bundle 模式下 `UNUserNotificationCenter` 的逻辑保持不变；仅 debug 模式下的浮动通知实现重构。

### 2. FloatingNotificationStack

新增一个仅负责 debug 浮动通知展示的栈管理器，职责包括：

- 保存当前活跃通知列表
- 为每条通知分配展示顺序
- 控制最多 3 条可见卡片
- 在超出上限时生成或更新 `+N` 聚合卡片
- 统一驱动新增、关闭、补位和展开行为

它是整个布局与状态的唯一协调者，避免每个面板各自计算位置，导致重叠或状态不同步。

### 3. FloatingNotificationCardPanel

每张真实通知卡片独立为一个 `NSPanel`，仅负责单卡片展示与自身交互，不负责全局布局。

单卡片内容结构：

- 顶部来源行：应用名 + session 信息
- 主标题：单行或双行内截断，作为第一视觉焦点
- 简短正文：较当前更短，限制在 1～2 行
- 关闭按钮：保留右上角，但提升触控区与对比度

### 4. OverflowSummaryPanel

当通知数量超过 3 条时，最底部位置展示一张聚合卡片，形式为 `+N`，表示还有 N 条隐藏通知。

该卡片不承载正文内容，只承担状态提示和入口作用。点击后按顺序展开隐藏通知，将它们补入可见区，而不是一次性全部展开。

## 视觉设计

采用用户确认的 B 方向“信息卡片”风格，但进一步做紧凑化处理：

- 深色卡片底色，保留与终端一致的深色氛围
- 更清晰的上下内边距与信息分层
- 圆角比当前更柔和，但不过度夸张
- 使用轻量描边或阴影增强浮层边界
- 关闭按钮透明度与 hover 态更清晰
- 正文做更严格截断，避免长文档摘要把卡片拉得过高

目标不是做强装饰，而是在现有风格基础上做到“更精致、更干净、更容易扫读”。

## 布局与交互行为

### 布局规则

- 所有通知固定在右上角区域展示
- 新通知插入栈顶
- 卡片之间使用固定垂直间距
- 可见上限为 3 条
- 超出上限时，最底部改为 `+N` 聚合卡片

### 生命周期

- 新通知到达：新卡片从右上轻微滑入，已有卡片整体平滑下移
- 点击卡片：跳转到对应 session，并移除当前卡片
- 点击关闭按钮：仅移除当前卡片
- 卡片移除后：下方卡片平滑上移补位
- 点击 `+N`：按顺序展开隐藏通知，逐步补入可见区域

### 常驻策略

通知不自动消失。存在即表示仍待处理，直到用户点击或关闭。

这样可以避免用户在专注终端时错过通知，也与当前希望“常驻直到处理”的要求一致。

## 实现范围

### 受影响文件

核心修改预计集中在：

- `Sources/PowerShell/Services/NotificationManager.swift`

如果为了结构清晰拆分新文件，也仅限通知相关实现文件，不扩散到终端、会话或 NL 逻辑。

### 不改动内容

以下不在本次范围内：

- `OutputMonitor` 的通知触发机制
- `HookNotificationServer` 的解析与投递机制
- `SessionManager` 的 session 切换语义
- App Bundle 模式下的系统通知样式
- 侧边栏未读徽标逻辑

## 测试与验证

### 手动验证

1. 单条通知出现时，确认新卡片样式更紧凑且层次清晰
2. 连续触发 2～3 条通知时，确认右上角纵向堆叠且不重叠
3. 连续触发超过 3 条通知时，确认出现 `+N` 聚合卡片
4. 点击任意通知时，确认跳转到对应 session 且卡片移除
5. 点击关闭按钮时，确认只关闭当前卡片且下方补位顺滑
6. 点击 `+N` 时，确认隐藏通知按顺序补入可见区
7. 验证卡片不会无限增高，长正文会正确截断

### 构建验证

- 运行 `swift build`
- 如环境允许，运行 `swift run PowerShell` 做浮动通知 smoke test

## 非目标

以下内容不在本次范围内：

- 重做系统原生通知样式
- 增加通知分组、筛选、搜索等通知中心能力
- 为不同通知类型设计差异化配色体系
- 增加自动消失、定时收起或静默模式
- 修改通知文案来源和内容生成逻辑
