# 通知栏视觉与堆叠优化设计

## Context

当前 debug 模式下的通知已经升级为右上角浮动卡片，但实际体验仍有两个问题：

1. 同一个终端连续产生多条通知时，会出现多张内容相近的卡片，信息重复且干扰视线。
2. 当前仍保留“最多展示 3 张卡片”的折叠逻辑，不符合最新需求，也让用户难以直接看到所有有通知的终端。

本次目标是在不改变通知来源和点击跳转能力的前提下，将 debug 模式下的浮动通知从“按通知条目展示”调整为“按终端聚合展示”，让每个终端始终只对应一张卡片，同时去掉 3 张上限与 overflow 逻辑。

## 目标

- 同一个终端的通知始终聚合到一张卡片上
- 卡片展示该终端最新一条通知内容
- 当同一终端存在多条未处理通知时，额外显示“还有 N 条”提示
- 所有终端卡片都直接展示，不再限制最多 3 张
- 新通知到来时，对应终端卡片移动到最上方
- 点击卡片后跳转到对应 session，并将该卡片移除
- 点击关闭按钮时，仅移除该卡片，不跳转
- 不改变 App Bundle 模式下的原生系统通知行为

## 推荐方案

采用“按终端聚合 + 最新内容覆盖 + 无限纵向堆叠”的方案：

1. 将当前 `FloatingNotificationCenter` 从“通知列表”改为“终端聚合卡片列表”
2. 每个 `sessionId` 只保留一张活跃卡片，卡片内容始终同步为该终端最新一条通知
3. 卡片额外维护该终端未处理通知数，用于展示“还有 N 条”提示
4. 所有卡片统一按最近通知时间倒序排列，最近收到通知的终端永远显示在最上方
5. 点击卡片后视为该终端通知已处理，直接移除整张卡片

该方案与用户最新需求完全一致，交互语义也最直观：一张卡片代表“这个终端当前还有待查看的通知”。

## 备选方案与取舍

### 方案 A（推荐）：按终端聚合，点击即清空卡片

优点：

- 最符合“同一个终端只展示一张卡片”的目标
- 信息重复最少，可读性最好
- 点击语义清晰：进入终端即视为处理完成
- 状态模型简单，便于测试和维护

缺点：

- 点击后该终端历史未处理通知不会逐条保留在浮层中

### 方案 B：按终端聚合，但点击后只消费最新一条

优点：

- 理论上保留更多通知历史

缺点：

- 用户点击后卡片仍可能残留，交互预期较差
- 卡片状态更新更复杂，不利于理解和维护

### 方案 C：继续按通知条目展示，只取消 3 张上限

优点：

- 改动范围最小

缺点：

- 无法解决同终端多条通知重复占屏的问题
- 不满足“来自同一个终端的通知全部展示到一张卡片上”的核心目标

## 组件设计

### 1. NotificationManager

保留 `send(title:body:sessionId:)` 作为统一入口，但在 fallback 路径中继续将通知投递给浮动通知 presenter，不改变外部调用方。

App Bundle 模式下 `UNUserNotificationCenter` 的逻辑保持不变；仅 debug 模式下的浮动通知聚合行为调整。

### 2. FloatingNotificationCenter

继续作为 debug 浮动通知的状态协调者，但内部模型改为“按 session 聚合”：

- 保存当前活跃终端卡片列表
- 每张卡片包含 `sessionId`、当前标题、最新正文、未处理通知数、最近更新时间
- 同一终端新通知到来时，更新已有卡片而不是追加新条目
- 将刚收到通知的终端卡片移动到排序最前面
- 支持按 `sessionId` 直接移除整张卡片

它不再维护 overflow 展示状态，也不再区分“可见通知”和“隐藏通知”。

### 3. FloatingNotificationCardPanel

每个终端卡片仍独立为一个 `NSPanel`，仅负责单卡片展示与自身交互，不负责全局布局。

单卡片内容结构：

- 主标题：当前最新通知标题，作为第一视觉焦点
- 最新正文：显示最新一条通知内容，限制在 1～2 行
- 未处理提示：当未处理数大于 1 时，显示“还有 N 条”
- 关闭按钮：保留右上角关闭操作

不再存在 summary/overflow 专用卡片。

## 视觉设计

延续当前已确认的深色信息卡片风格，但视觉层次围绕“单终端聚合”做简化：

- 深色卡片底色，保持与终端一致的视觉氛围
- 标题、正文、未处理提示三层信息清晰分离
- 未处理提示使用较弱但可读的辅助样式，避免与正文竞争视觉焦点
- 保持紧凑卡片高度，避免大量卡片时过度遮挡终端
- 所有卡片使用统一尺寸与垂直间距，形成稳定的列表感

目标不是增加装饰，而是让“哪个终端需要处理、最新发生了什么、还有多少条”一眼可扫。

## 布局与交互行为

### 布局规则

- 所有通知卡片固定在右上角区域展示
- 每个终端最多只有一张卡片
- 卡片按最近收到通知时间倒序排列
- 新通知到来时，对应终端卡片移动到最上方
- 不再限制最多展示 3 张卡片
- 不再存在 `+N` 聚合 summary 卡片

### 生命周期

- 新终端首次收到通知：创建一张新卡片并插入顶部
- 已有终端再次收到通知：更新该卡片为最新内容、未处理数加一、并移动到顶部
- 点击卡片：跳转到对应 session，并移除整张卡片
- 点击关闭按钮：仅移除整张卡片，不跳转
- 卡片移除后：下方卡片整体上移补位

### 常驻策略

通知仍不自动消失。只要卡片存在，就表示该终端仍有待处理提醒；点击进入终端或手动关闭，即视为处理完成。

## 测试与验证

### 自动化验证

1. 同一终端连续收到多条通知时，只保留一张卡片，标题和正文更新为最新通知内容
2. 同一终端存在多条未处理通知时，正确显示“还有 N 条”提示
3. 多个终端同时有通知时，最近收到通知的终端卡片排在最上方
4. 卡片数量超过 3 张时，仍全部继续向下排布，不产生 summary overflow
5. 点击卡片后，触发 session 跳转并移除对应卡片
6. 点击关闭按钮时，只移除当前卡片，不触发跳转

### 手动验证

1. 同一终端连续触发多条通知，确认界面始终只有一张对应卡片
2. 检查卡片正文始终显示最新一条通知内容
3. 检查“还有 N 条”提示与真实聚合数量一致
4. 多个终端交替触发通知，确认最新活跃终端总在最上方
5. 连续触发 4 张、5 张以上终端卡片，确认所有卡片都继续向下排列
6. 点击卡片后，确认跳转到对应终端且卡片消失
7. 点击关闭按钮后，确认卡片消失但不会切换终端

### 构建验证

- 运行 `swift build`
- 如环境允许，运行 `swift run PowerShell` 做浮动通知 smoke test

## 非目标

- 增加通知分组、筛选、搜索等通知中心能力
- 增加自动消失、定时收起或静默模式
